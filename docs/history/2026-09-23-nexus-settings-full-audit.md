# Nexus 整个设置页核对（2026-09-23）

## 范围与结论

用户明确指定 Nexus 设置页，因此本轮覆盖 `SettingsView`、`HarnessPreferencesPanel`、`HarnessSourcePanel`、`NotificationSettings` 及其调用链，不扩大为上游全部插件内部设置。

按源码语法树提取到 73 个控件／动作／表单生成位置：14 个 field/choice 调用、28 个原生输入或路径控件模板、31 个动作按钮。这是代码位置计数，不是 73 个独立配置项：动态类别、条目会展开，模板也会复用；无上限的参数行与补丁条目不能按数量穷举。原始清单在 `.tmp-ui-audit/nexus-settings-controls.json`。

**不能签署“所有配置项的最终运行效果已真机通过”。** 下表逐项区分已取得的证据和剩余边界。后台业务、外部服务、系统集成不能用保存请求或单元测试替代。

## 本轮实际修复

- Agent 日志级别传递失败不再静默吞掉；只在桌面环境调用，浏览器预览不制造原生命令错误。
- 开机启动设置失败不再仅变成“不可用”：保持原选择并展示实际错误，允许重试。
- 补充双语说明：Node/pnpm/Git 路径覆盖用于 Web/CLI 及依赖工具，官方 Desktop 使用其匹配运行时，避免误认为覆盖已用于 Desktop。

日志级别跨重启失效的早期假设已撤销：`commandStartupStatus` 已在启动前恢复本地选择。本轮没有保留针对该错误假设的后端持久化改动。
