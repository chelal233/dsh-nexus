# Nexus 0.1.2 后续计划

## 2026-09-11 外部 Review 收尾

R1～R4 修复批次已通过外部终审，无未决分歧。用户随后授权修复剩余记录项，并明确首发版本没有历史兼容压力；10 项已修复，旧二进制兼容项标为不适用，见 [问题修复记录](known-limitations.md)。虚拟机/真机验收仍由用户执行；工作区提交及后续交付节奏另行确定。

## 本轮修复与公开准备

- 损坏诊断单项保留并告警，不再阻断健康历史与清理预览；目录权限错误仍明确报告。
- 恢复产物增加最新索引、有界分页和按 ID 重新打开；未来或非法索引保留，索引失败不否定产物生成成功。
- Restart 使用持久请求回执，未知响应重试不重复重启。
- 启动准备支持按当前操作 ID 取消；旧 ID 不影响新操作，进程创建前关闭取消窗口，取消不自动重启旧实例。
- 自检工具故障导航到运行时设置，安装中断导航到维护。
- 独立复核发现的索引保护与分页边界已修复；慢 Node 假程序联动单独验证取消后的进程退出及清理，不等同于真实 Harness 验收。
- GitHub 基础说明、反馈模板与只读 CI 已开始补齐。第三方许可完整归档、计划公开历史检查、远端 CI 和真实机器验收仍待完成，见 [公开发布准备](github-release.md)。

完整门禁及安装包结果以对应新构建记录为准；不能把定向测试或已添加的 CI 配置当作发布全部通过。

更新：2026-09-09。代码、自动化、包内校验与用户真实验收分别记录。最终结果以新构建的 `verification.json`、`package-verification.json` 和 `machine-acceptance.json` 为准，旧包不能代替新包。

## 本轮关闭的缺陷

- 补丁重复启用／禁用及旧式缓存路径引用不会绕过失败阻断；子进程失败按实际启动时的补丁集合归因。
- GitHub branch、tag、commit 永久链接可选择，固定 commit 与来源身份绑定本地缓存；启动不下载。
- 关键记录损坏或未来格式导致初始化失败时进入只读 Agent，保留原文件，提供鉴权后的诊断与退出，拒绝启动和正常修改。
- 自动崩溃诊断由后台观察触发，不依赖界面轮询，成功后确认，每次运行最多三次尝试。
- 前轮恢复冲突、清理预览、慢补丁下载、空行／web 别名、孤儿请求、草稿和被动卸载修复一并保留。

定向回归及独立复核已完成；最终完整门禁和包内校验另存构建记录。不据此宣称没有未知缺陷。

## 1. 优先完成真实验收

用户手动执行 [验收清单](manual-acceptance-0.1.2.md)，Codex 不使用 Computer Use。

- 新构建首次安装、覆盖升级、普通卸载重装、清理后重装及数据保护。
- RC1 或更早版本的启动、Web、托盘和工作站终端、已安装版本离线启动。不使用 0.1.3-alpha.1。
- 可信 GitHub 补丁的 branch/tag/commit 获取、缓存离线运行、失败后主动禁用、切换引用重新获取。
- 草稿跨页面及冲突保留、正常快照恢复、恢复模式、退出方式、中英文和 MSI `/passive`。
- Defender 开启时单独记录；不支持休眠则记不适用。精确中断和 UNC 专项不要求用户刻意制造，无新证据记未覆盖。

## 2. 本批补齐与明确边界

| 内容 | 本批结果 | 验收边界 |
|---|---|---|
| 界面分组 | 独立版本入口；设置按 Harness、运行时与启动、修复、应用信息分组，隐藏分组保留草稿；简化面板与小屏布局 | 类型、渲染和 i18n 回归；实际视觉与键盘操作由用户验收 |
| Nexus 记录恢复 | 按真实历史时间选择，一键备份并恢复配置档目录记录；Agent 重启后持久暂停 Harness | 仅恢复当前配置档选择和已知名称；不覆盖运行所有权、事务、Harness 文件。未来/未知格式保留，无历史不能虚构恢复点 |
| GitHub 补丁 | 按页列出 branch/tag，保留手输；下载候选、摘要/提交号/脱敏差异预览，确认后固定内容应用；取消释放配额 | 启动不联网；真实 GitHub 查询和断网应用由用户验收 |
| Canary | 独立临时 HOME、逐轮受管进程、有界组合缩小、取消及中断清理；进度、组合、耗时和最多 10 份历史；每轮依赖复制前检查目标卷空间 | 数据目录隔离不等于系统安全沙盒；命令、面板和实际交互明确未验证，不自动禁用插件；进度及历史定向回归已通过，完整门禁以构建记录为准 |
| 权限与进程修复 | Canary/兼容检查使用新建私有工作目录和私有原始结果；整棵进程树退出后才清理/发布 | 不修改用户父目录权限；生产兼容检查失败由用户明确选择插件后重试 |

自动化故障注入使用临时目录和 localhost；不要求用户损坏实际 profile。自动替换原始记录、通用插件交互适配器仍不支持，不将这两个边界标成已完成自动化能力。

## 3. 已明确的产品边界与延期事项

- **延期：**发布签名及发行供应链认证、Nexus 更新检查／自更新。
- **本次不做：**系统凭据库、完全离线首次安装、多用户服务模式。现有 Agent 本地接口认证仍需保留；Harness 的访问密钥不替代 Nexus 接口授权。
- **遵循上游：**插件依赖处理交给 Harness 插件市场；Nexus 不另行实现卸载后的依赖安装和整理。
- **外部 Harness（已实现，待真实验收）：**直接选择用户准备好的程序目录，仅保存关联，不复制、构建、安装依赖、更新或删除。DSH_HOME 与项目工作目录分别配置。解除关联不删除原目录；Nexus 自身只读，用户运行的 Harness 自身仍可能写入程序目录。
- **外部目录复核范围：**目录身份、全树路径/类型/大小/修改时间及关键入口/清单内容摘要，检测日常文件变化后要求重新确认。此检查不认证上游发行来源，也不保证识别故意保留大小与时间的非关键文件篡改；不会为每次启动读取全部依赖内容。
- **本轮优化（已实现，待真实验收）：**轮询、Canary 进度及有界历史、空间预检与分类、补丁预览有效期、恢复辅助。恢复现改为选择时间后自动备份与原子替换配置档目录记录；私有备份不自动清理，存在快照时补丁缓存保守保留。完成和验证结果以本轮最终构建记录为准，不沿用上轮通过结论。

实际 RC1 目录的 Rust 只读检查样本为 23.43 秒，预算 30 秒。启动现由后端本次事务完整检查一次，复用验证上下文并在启动前轻量核对配置/profile/身份及关键文件；用户主动检查仍独立执行。普通健康查询不扫描源目录，不声称大型目录即时启动。

## 4. 用户旅程复核修正

- 外部来源零版本槽时开放正确的启动与 DSH 终端入口，首次引导提供下载安装与已有目录两条路径。
- 外部模式下版本槽操作明确不改变外部启动来源；来源草稿冲突可以主动放弃并重载。
- 检查阻断可定位修复页并返回重查；Canary 要求先由用户明确停止 Harness。
- 恢复产物在重开后仍可选择核对，正常 Agent 仅提供受限只读操作。
- 第二轮用户视角复核补正自定义命令来源标签与结构化自检错误显示。静态旅程、SSR 和临时目录测试不替代真实桌面验收。

Nexus 定位为标准 Harness 启动器。新增超出该范围的行为需明确影响并由用户决策；不得借诊断或恢复之名自动修改上游源码或生产配置。保持不迁移用户数据、Nexus 安装升级卸载不现场编译的边界。
