# Harness 设置与诊断验收（2026-09-23）

本轮覆盖 Nexus 展示的 Harness 设置，不包括上游插件内部所有设置。代码仍在现有任务工作树，未发布、未覆盖 D 盘。以下明确区分源代码能力检查、自动化进程验证与官方应用实机验收。

## 已确认并修复

- 设置能力检测原先依赖 0.1.2-rc.1 白名单，上一轮仅放行新版 Web 端口。本轮改为读取所选产物的具体设置能力，不再按版本字符串放行。缺失能力会明确拒绝，不静默丢弃。兼容缓存适配器标识同步升级。
- Desktop 之前只读取 Nexus 数据目录设置，其余通用设置未传入。现在将通用环境值传入 Desktop 的实际工作进程；不把地址或提示词写进启动配方文件。
- 显式 `--port 0` / `--port=数字` 和 `--no-open` 不再仅因参数数量不同而关闭单次启动加速。未知参数仍保留原隔离检查。
- 后续自检通过不再遮蔽仍然失败的进程；分别轮询到的旧进程日志不能冒充当前错误。
- 浏览器 active 时仍显示本次宿主启动报告中的可选插件警告；不因此禁止使用已就绪浏览器，不把一般后台错误当作启动失败。
- 进程资源锁归类为资源所有权问题，不推荐删除锁或禁用无关插件。端口冲突优先于其后的大量等待服务列表。

## 诊断记录验收

读取本机 diagnostics 中每份 `run/harness-log-session.json` 指向的 stderr，按 run_id 去重，不把包内复制的历史日志重复计入当前故障：共 17 次运行。

- 9 次启动阻塞：EADDRINUSE，端口 3080 或 3852。后续等待服务是连带结果。
- 2 次显式启动警告：插件接口不兼容。归类与保留原始证据，不修改上游插件实现。
- 1 次配置档限制，1 次缺失模块。
- 4 次无可确认阻塞证据：其中 1 次 stderr 为空、1 次可选 bsk CLI 缺失提示、另 2 次没有错误行。不能把它们伪报成插件故障。
- 最新运行日志另有 task-board ledger 被进程占用；本轮补了根因和可选启动警告展示，不删除用户锁、不终止未知进程。
