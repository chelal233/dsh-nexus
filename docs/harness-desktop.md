# Harness 官方 Desktop

[English](harness-desktop.en.md)

Nexus 直接运行当前受管 Harness 版本中的官方 Electron 客户端，不再维护替代客户端。Web 的浏览器入口保留；CLI 对 `desktop` 专用配置的限制也保留。

在工作台停止 Web 后，选择「启动官方 Desktop」。Nexus 校验自带运行时，调用该 Harness 版本的本地准备脚本，再启动官方原生窗口。不会使用开发调试端口，也不会为 Desktop 注入 Nexus 的 Web 兼容插件。旧 `--nexus-shell` 入口转到官方 Desktop。

## 离线交付

- 用户只需要取得 Harness 版本。Electron、Python、Node 和锁定的 Python 依赖随 Nexus 交付；Desktop 准备过程禁止联网下载。
- 完整离线导出包含匹配的 Desktop 运行时。使用旧的便携 Node/pnpm 时，导出会从 Nexus 自带资源补齐 Desktop；没有匹配资源则明确拒绝生成不完整包。
- 导入不安装在线依赖。导入后优先使用包内运行时，从本地资源重新生成 Desktop 的临时链接和运行目录。
- 依赖缺失、校验失败或版本不匹配时，提示修复 Nexus 或使用匹配的完整离线包，不会静默切换版本或在线补装。
- 导出「仅配置/数据」仍是用户选择的部分包，不包含 Harness 或运行时；它不能替代完整离线发行包。

Nexus 发布准备使用 `prepare:desktop`。从 `desktop/desktop-runtime-lock.json` 指定的官方提交取得源码和运行时锁文件，校验固定 SHA-256，再取得锁文件中的 Node、Python 和 wheel。各目标平台原生构建时调用官方组装脚本与完整自检，包括 Python 分发检查、文档读写、Node 和 pnpm 检查；通过后打包 `primary.tar.gz`。全新 CI 不依赖维护者目录或预热缓存。`NEXUS_HARNESS_DESKTOP_SOURCE` 仅可复用匹配的本地下载文件。

日常安装只保留 Nexus 使用的一套 Electron。Desktop 以同一可执行文件的独立进程启动，由轻量入口设置官方应用路径、名称、版本和原有源码运行模式，然后导入官方 `lib/main.js`。它不启动 Nexus 窗口、Agent 或自制客户端，也不修改 Harness 源码。macOS 继续使用 Nexus 自身的签名应用结构。

Nexus Launcher 的 Electron 精确版本与官方 Desktop 运行时锁保持一致，当前为 `44.0.0`。打包时检查声明版本、已安装版本和 Desktop 锁；升级时必须一起验证和更新。首次准备只校验并解压本地预组装资源、生成官方依赖链接；再次启动检查文件元数据和链接目标，未变化时复用。损坏或缺失时从已校验的本地资源重建，不联网。长操作处于可中止的准备子进程，界面显示阶段、耗时和取消入口。

完整离线导出另外携带匹配的 Electron 宿主备份（`host.tar.gz`），只包含应用二进制与引导资源，不包含用户数据。接收机版本相同时继续共享 Nexus；不匹配时从包内提取宿主启动，避免让离线包依赖接收机恰好已有某个版本。导出先验证宿主支持官方 Desktop 入口及应用摘要。旧 schema 1/2 离线包保留其独立 Electron 回退。完整离线包仅在相同操作系统和架构间迁移；不匹配时拒绝导入。Unix 包保留可执行权限和相对链接。macOS 宿主备份保留完整签名 .app，导出和提取后均校验签名；Windows 保留限定的宿主文件。

GitHub 构建按“基础运行时 → Desktop 离线资源与原生自检 → 发布清单 → 打包 → 安装包校验”执行。安装包校验执行共享 Electron 的版本探针并解压验证预组装依赖。资源缺失或校验失败会终止构建，不会把下载推迟到用户首次启动。

Web 的兼容检查以并行文件清单校验缓存，排除官方 Desktop 的生成目录；插件、配置、环境、文件元数据或链接目标变化仍使缓存失效。手动自检继续强制执行探针。无法完整验证清单时仍回退到实际检查。

当前固定的官方运行时支持 Windows x64、macOS x64／ARM64。上游锁文件未声明 Windows ARM64 或 Linux ARM64 Desktop，因此这些 Nexus 包携带经校验的不支持标记，继续提供 Web，隐藏 Desktop 入口；不会混装 x64 运行时冒充 ARM64。

## 状态边界

「Desktop 进程已启动」只证明原生客户端进程存在，内部插件就绪情况和运行时业务错误由官方客户端呈现。Nexus 展示准备错误、进程退出和可重试状态；关闭启动器不会关闭 Desktop。修改版本、配置和导出数据前先关闭 Desktop，启动器会阻止并发写操作。

当前锁定基线为 Harness `0.1.6-alpha.2`、Electron `44.0.0` 及该版本锁定的运行时。其他版本必须通过产物和锁文件兼容检查，不因版本号接近而猜测兼容。其他平台未在本次工作中真机验收。Windows 本地回归与 WSL x64 的 Unix 离线往返、进程组停止检查已执行；v0.1.8 的五个平台目标已通过 CI 与安装包检查，包括 macOS 签名应用结构／离线宿主检查及 Linux ARM64 安装包冒烟；这不等于所有平台上的完整 Harness 业务真机验收。

平台范围取 Harness 与 Electron 的交集。Linux ARM64 仅构建 Nexus 图形启动器和 Web 入口，提供 AppImage、DEB、RPM 构建目标，不包含自制 Desktop。Linux Agent 在 glibc 2.28 环境构建并校验 ABI；安装包格式支持不代表任意发行版均可运行。

macOS 签名会改写内嵌二进制。发布流程在内部签名完成后刷新资源摘要，再重新封装外层应用签名，启用公证的构建再由打包器提交公证；安装校验使用签名后的摘要。ad-hoc 签名检查不代表已完成 Apple 公证。

## 托盘控制

托盘将「浏览器版」和「官方桌面版」分为子菜单，分别提供启动、打开和中止；配置、维护及退出操作独立分组。官方桌面版子菜单仅在当前受管 Harness 和平台支持时显示。Web 和 Desktop 共用版本与数据，因此启动和配置写入互斥；正在准备、运行和中止时会限制冲突操作。配置切换入口打开启动器的配置页面，不会直接切换配置。

「官方桌面版 → 中止桌面端」由启动该实例的后台工作进程结束它拥有的进程树，准备期间也可以取消。旧版启动器已启动的实例需要先手动关闭官方窗口。操作失败时保留启动器并显示错误。

「退出启动器（Harness 继续运行）」保留正在运行的 Harness；「中止所有服务并退出」先中止 Desktop，再由 Agent 执行 Web 和 Agent 的停止，成功后才退出。
