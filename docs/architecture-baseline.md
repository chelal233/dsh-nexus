# Nexus 当前架构与支持边界

本文描述 0.1.2 候选版本的实现边界。构建验证记录与真实机器验收是不同证据；实际交付以同一构建编号的资源清单和验证记录为准。

## 运行组成

Nexus 面向 Windows x64 普通桌面用户。原生 Launcher 提供工作站、设置、托盘和独立启动诊断；后台 Agent 管理 Harness 进程、版本槽、配置及恢复事务；nexusctl 使用同一受保护的本地接口。关闭主窗口默认隐藏到托盘；退出窗口与停止服务是不同操作。

安装包携带预编译 Nexus 程序和完整 Node/npm/pnpm、Git 运行组合。Nexus 安装、覆盖升级和卸载只操作预编译产物，不调用客户机编译环境。首次安装或切换到尚未安装的 Harness 版本可以使用内置运行时执行上游依赖安装和构建。若上游依赖要求 Python、Visual Studio 等原生工具，Nexus 保留原始错误，能够可靠识别时附加说明，不修改上游源码或自动安装这些开发工具。

原生 WebView2 尚未安装时，安装包附带的引导程序可能需要网络。已经安装且依赖完整的 Harness 可离线启动；完全离线首次安装不在计划中。发布签名和 Nexus 自更新延期；系统凭据库与多用户服务模式本次不做。插件依赖遵循 Harness 插件市场，Nexus 不另设依赖管理流程。

## 路径与数据所有权

程序目录、Nexus 数据目录、Harness 数据目录和项目工作目录分别处理。Nexus 自有状态默认位于当前用户 LocalAppData 下的 Nexus；版本槽、下载暂存、事务记录、日志和诊断属于此数据根。受保护事务依赖本地普通目录、文件身份、原子替换与同卷重命名；不将 UNC 共享或可移动盘承诺为 Nexus 状态存储支持范围。

Harness 数据目录通过已验证版本的 DSH_HOME 能力设置；空值继承上游原始默认值。设置只改变访问指向，不搬迁或删除旧数据。保存和启动前检查路径可访问性及能力支持。项目目录由 Harness 的会话/工作区功能管理，不用 DSH_HOME 替代，也不修改 Nexus 启动版本槽所需的工作目录。交互 DSH 终端初始位于 profile 目录，用户可自行切换目录。

普通卸载与删除 Nexus 应用数据分开。显式清理自有数据可能删除已安装的 Harness 程序槽；自定义 Harness 用户数据有独立保护，不能因路径大小写、别名或重装残留而误删。共享目录上的 Harness 数据是否满足其自身依赖和访问要求，仍需在实际环境验收，不承诺所有网络文件系统通用。

## 本地通信与授权

Agent 动态选择回环监听端口，并通过独立发现文件发布身份。除最小健康检查外，接口要求当前用户私有凭据；localhost、端口和实例编号均不是授权。协议 v2 将方法、路径、实例、时间和唯一请求标识纳入认证，并分别加密请求和响应，避免旧端口被其他本地服务占用时泄露配置。请求有时效、重放与体积限制，浏览器来源受到检查。

凭据以当前用户私有 ACL 保存，读取检查文件类型、身份和边界。凭据和 Harness 认证索引不进入诊断。原生 GUI、CLI 和预编译卸载辅助程序使用同一授权通道。对已知旧版本的卸载兼容仅在验证旧程序身份及端口进程归属后适用；新版本认证失败不得降级为匿名停止。

纯浏览器 Vite 页面属于界面开发预览，不获得原生凭据，也不能据此承诺完整控制功能。需要控制 Agent 时使用原生开发 Launcher 或 CLI。

## 配置与版本能力

读取配置同时返回原始文档修订号。GUI 保留草稿所属修订，保存和恢复检查预期修订；过期草稿冲突时保留编辑内容，不能覆盖新配置。CLI 也先读取再提交。此协调保护同一 Agent 的调用者，不将任意外部编辑器声称为参与原子事务。

Nexus 配置和关键记录有格式版本及未知字段保护。不支持的新格式保留原件并拒绝危险写入，不静默迁移用户数据。这一保护从支持该规则的版本开始成立，无法追溯保证更早发行的二进制安全读取未来格式。

Harness 参数能力集中按版本和实际 bundle/profile 证据识别，未知版本允许原始空配置继承，显式不支持的设置阻断并说明。Web、SDK 和 PTC 能力不混为一谈。具体配置范围见 [Harness 配置说明](harness-configuration-0.1.2-rc.1.md)。设置旁说明影响对象、下次启动生效或需要重启，以及可用的撤销方式。

## 进程与恢复

Agent 必须正常才能进入 Harness 恢复模式。恢复模式主动暂停 Harness 启动，仍允许管理 profile、配置、插件和快照；修复后重新检查再启动。Agent 自身启动失败由 Launcher 独立诊断处理，不能用恢复模式掩盖。

Harness 后代受 Windows 进程树所有权管理。工作站和托盘分别提供启停、Web 和交互 DSH 终端入口。托盘状态超期禁用控制并引导打开窗口。终端使用固定命令源与环境数据传参，持久登记进程身份和版本占用后才允许执行 DSH；登记期间异常退出不会留下能够使用未受保护槽的终端。存活终端保护其版本免于清理。

安装、发布、切换、快照恢复和清理共用互斥边界与持久恢复记录。异常退出后按阶段继续或撤回；不依赖清空记录或反复重装。回退、冷切换、离线导入和快照恢复的初始请求先持久接纳，重复编号只查询原回执；历史最多256项，有效重试窗口24小时，窗口内不驱逐。Launcher按数据根持久保存未决引用，关闭重开仍保留。中断结果不明时不自动重做，用户先核对当前状态，再明确允许新尝试。恢复记录的原始事务目标用于核对，面向用户的可回退状态另外过滤，避免旧记录没有新健康证据时永久阻塞恢复。

已安装只代表程序槽可用；进程已启动不代表健康。已知良好回退版本要求受管运行的实际就绪证据，绑定版本、profile、配置修订与运行身份。入口和 manifest 指纹防止同名替换沿用旧证据，但不是整个上游依赖树的完整性认证。

## 日志、空间与诊断

活动日志使用 Windows 稀疏分配回收旧内容，保留每流 8 MiB 故障尾部和经私有持久验证的认证证据。文件身份、追加偏移和逻辑长度不变；资源管理器显示的逻辑长度可能持续增加，实际磁盘分配另行报告。扫描有积压时分小批追赶，未扫描区域不回收；持续输出超过约 5 MiB/s/流时仍可能积压，因此这是受支持文件系统上的容量回收机制，不是所有输出速率下的硬配额。不支持或不能安全处理时保留原始日志并报告限制，不通过截断破坏会话入口。

安装、离线导入导出、快照采集和恢复按实际目标卷及当前用户可用配额估算峰值，包含暂存与必要备份。预算是检查而非预留；其他程序写入、未知在线构建输出和外部包缓存仍可能耗尽空间。在线首次构建使用保守下限估计，不能保证任意上游项目都够用。

扫描、探测和诊断限制读取量、执行预算和并发；超时后未结束的后台工作仍占有额度，避免重试积累。文件系统阻塞调用不能被这些等待预算强行取消，故不承诺所有存储故障下都有硬实时期限。

Agent 可导出当前失败的脱敏上下文与有界日志。Agent 不可用时，Launcher 从固定自有路径导出构建身份、启动错误和有限日志，不依赖 Agent 接口。源文件过大、未知或无法安全读取时记录缺失而非无限扫描。原始错误保持可见和可复制；解释不取代原始文本。

## 发布与验收

版本号、唯一构建编号、编译程序身份、内置运行时版本和资源 SHA-256 清单必须一致。打包使用 Cargo 实际报告的产物路径，避免自定义输出目录混入旧程序。发布候选验证绑定源文件指纹和构建编号，分别记录自动化测试、包内资源核对及未执行项目。未运行或被环境限制的检查不能标为通过。

真实虚拟机验收由用户手动执行，按用户要求停用 Computer Use。Codex 负责代码、自动化检查、安装包校验及可复现的手动清单；首次安装、覆盖升级、重装、选择清理后重装、已安装版本离线启动、托盘和交互终端由用户确认。中断与故障注入由自动化回归承担，不要求用户破坏 profile。自动化与静态复核通过不替代真实交互结果，安装包仍须标明待实机验收项。

### 2026-09-09 补充边界

Canary 使用独立临时 HOME 和逐轮受管 Job，进程树确认停止后才读取结果并清理；不写生产 profile、兼容报告或补丁失败策略。Windows 私有目录使用可继承当前账户/SYSTEM ACL，Unix 为 0700；兼容检查的请求、原始结果和 stderr 同样位于私有工作目录。功能交互没有通用适配器，显示未验证。生产兼容探测先收尾进程，再单独 finalize；失败保留原错，由用户明确选择后重试。

只读恢复向导只生成私有原件备份与经过验证的 profiles 替代文件；不自动覆盖原件，不降级未来格式。最终手工替换前必须停止服务并检查原件摘要。补丁预览绑定配置修订、来源和缓存摘要；应用不重下载，取消释放候选配额。
