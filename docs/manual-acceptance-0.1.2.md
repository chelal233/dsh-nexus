# Nexus 0.1.2 手动验收

本轮新增可选观察：启动准备较慢且出现“取消启动”时，可点击取消，等待安全退出，预期不会继续生成 Harness 进程；若这是重启，已经停止的旧实例不会自动恢复。若启动很快、没有可取消阶段，记录“未覆盖”，不要人为破坏 profile 或反复中断机器。重复请求、超过 64 条恢复历史及损坏诊断隔离主要由临时目录自动化回归验证，不要求手工构造。

本轮由用户操作，Codex 不使用 Computer Use。请使用本次交付的明确构建编号，勿与同为 0.1.2 的旧包混用。构建编号及 SHA-256 以随包的 verification.json、package-verification.json 为准。

EXE 可选择简体中文或 English；MSI 分为 `zh-CN` 和 `en-US` 两个语言文件。任选一种安装即可，不需要把三份包都安装一次。

你只需要完成下表中的普通操作，不需要破坏 profile、抢时间杀进程或伪造故障。卸载只在测试虚拟机执行；开始前保留 baseline 检查点，以及自定义 Harness 数据目录中的一个测试标记文件。Harness 选择 0.1.2-rc.1 或更早版本，不选择 0.1.3-alpha.1。

| 项目 | 操作 | 预期结果 |
|---|---|---|
| 1. 覆盖安装与身份 | 直接覆盖旧 Nexus，启动后核对构建编号；检查原 profile 和数据路径 | 新构建生效，Agent 在线，配置和标记文件保留；Nexus 安装不要求编译工具 |
| 2. 启动与常用入口 | 打开 Web；分别从工作站、托盘打开 DSH 终端，在终端输入 `node --version`、`npm --version`、`pnpm --version`、`dsh --help` | Web 正常打开；终端在当前 profile，命令可用；无需系统另装 Node/npm/pnpm |
| 3. 清理勾选回归 | 若有可丢弃的测试旧版本，勾选它后重新生成预览；没有候选项就只查看保护提示，不必专门制造文件或删除数据 | 新预览不继承旧勾选，删除数量归零；同一预览刷新可保留勾选；当前版本和 Harness 数据不可删除。没有候选项记“未覆盖勾选分支”，不是失败 |
| 4. 正常快照恢复 | 按下方四步添加无效应注释并恢复，不需要损坏 profile | 注释被恢复移除、Agent 在线，当前 profile 可检查和启动；没有实际内容对比时只记“恢复操作通过” |
| 5. 暂停、草稿与离线 | 进入恢复模式并重启 Agent；编辑设置但暂不保存，等待几次状态刷新，切到维护再返回设置；断网后启动已安装的 RC1 | 暂停状态保留；刷新和页面切换不丢草稿（关闭整个 Launcher 后不保留）；退出恢复模式不会自动启动；已装版本无需下载或构建即可启动 |
| 6. 卸载与重装 | 先普通卸载并重装；再在测试环境选择清理 Nexus 数据后重装；两次均检查测试标记文件 | 普通卸载保留已有数据；清理后新 Nexus 不显示已失效的安装成功记录；自定义 Harness 数据标记始终保留 |
| 7. 退出与诊断 | 分别试关窗、托盘保留服务退出、停止服务退出，然后重新打开 Nexus 并导出诊断 | 三种退出行为符合菜单；重新打开后 Agent 正常，诊断导出成功；不要求主动制造崩溃 |
| 8. 中英文界面 | 设置切换简体中文和 English，依次打开工作站、设置、配置与插件、维护，再查看托盘 | 按钮、标题、已知状态和提示跟随语言；用户名称、路径、技术标识和原始错误保持原文 |

## 第四项怎么做（无需损坏配置）

1. 停止 Harness，展开当前 profile，在“已保存的检查点”点“创建检查点”，记下新检查点编号。选有内容快照的新检查点，不选标为“仅旧版元数据”的记录。
2. 点“打开 settings.yaml”，用文本编辑器在文件末尾**新起一行**添加 `# nexus-acceptance-marker` 并保存。`#` 开头是 YAML 注释，不改变有效配置。不要修改其他内容；如果文件不存在或无法打开，记录这一情况，跳过内容对比。
3. 回到 Nexus，恢复第 1 步刚创建的检查点，等待明确完成结果。恢复期间保持 Harness 停止。
4. 关闭旧编辑器窗口（不要再次保存旧内容），重新打开 settings.yaml，检查刚添加的注释是否消失。最后正常检查并启动 Harness。若未恢复成功，只删除自己加的那一行注释即可撤销测试修改。

普通恢复通过不等于中断恢复通过，两者分别记录。快照只恢复声明范围内的配置内容及已安装版本指向，不覆盖完整项目或会话数据。

## 不要求用户手动制造的场景

- 清理执行中断、快照应用中断：旧构建已有真实进程中断证据，另有自动化回归；新构建未重新命中的分支仍单独保留状态。
- **D02 UNC 等价路径保护**：专用路径环境专项，不属于普通点击验收；自动化与真实 UNC 场景分开记录。
- **D32 发布冲突恢复**：需要精确命中发布阶段，属于专项回归，不再要求用户凭时机中断。已有自动化保护测试不冒充真实冲突命中。
- Agent 崩溃时的独立诊断：已有旧包真实证据；如果日常操作恰好发生，再用顶部诊断入口收集，不必主动制造崩溃。

上述场景无法复现时记“未覆盖”，不是用户操作错误，也不能因此要求反复重装。若出现自然故障，再提供下面的信息。

## 失败时提供什么

每个失败只需提供：**项目编号、构建编号、操作到哪一步、提示截图、发生时间、一键导出的诊断 JSON**。Agent 无法启动时使用 Launcher 顶部的独立诊断入口。安装或卸载失败时再附安装器详情日志；上游构建失败请保留完整原始错误。不要发送密码、API 密钥或未脱敏的配置文件。

回复示例：`项目 4 / 构建 xxx / 点恢复后失败 / 14:32 / 已附截图和诊断`。

休眠若虚拟机不支持，记“不适用”。Defender 开启时的检测结果单独记录；关闭 Defender 后通过不代表开启时已通过。界面已按模块重新分组，实际视觉、键盘和缩放仍需用户验收。


## 9. 运行配置补丁（不需要损坏 profile）

1. 新建两个普通 UTF-8 文件 `a.yml`、`b.yml`，每个只写 `[]`（上游接受的空补丁数组）。在设置的运行配置补丁列表添加其绝对路径，启用并保存。
2. 上移/下移切换顺序，保存后重开设置确认顺序保留；禁用一项，重启 Harness，应正常启动。列表顺序是 profile 配置后的附加层，后项处理前项的结果。
3. 停止 Harness，将其中一项路径改为自己明确不存在的临时文件：禁用时检查不受影响，启用时检查应明确阻断。删除该列表项即可撤销，无须触碰 profile。
4. 有自己信任的 GitHub/HTTPS 独立补丁文件时，可主动加载分支／标签列表，或直接输入引用。点击“预览远程补丁更新”，核对 commit、SHA256 和有界脱敏差异；此时设置尚未保存。点击“应用已预览补丁”才切换到候选，确认时不再次联网下载。预览十分钟后过期，改草稿或配置需重新预览。断网后重启，已应用缓存仍可用。无合适远程文件则记未覆盖，不下载不明配置。
5. 保持断网点击更新应报错，旧配置和摘要不变，但该启用项留下失败记录，启动会阻断。禁用该项并保存后才允许继续；恢复联网后可重新启用并主动下载。移除列表项不删除源文件。修改补丁配置需停止服务后保存并重新启动。
6. GitHub 文件可选择分支或标签类型并输入名称；仓库内文件路径单独可编辑（分支含 `/` 时务必核对文件路径）。主动下载后显示固定 commit 和 SHA256；修改 ref 后旧缓存不能直接启动，必须主动下载新选择。普通启动、刷新、自检都不访问 GitHub。
7. 启用补丁时不会提前自动打开浏览器，请在健康检查通过后使用 Harness 页面或打开入口。若补丁组合加载失败，Nexus 设置仍可用，但 Harness 页面不可用，也不会自动删除插件绕过；无法确定具体补丁时，按提示逐项禁用并保存后检查。无需故意损坏 profile。

远程文件仅支持无 URL 凭据/查询参数的 HTTPS，GitHub 使用文件 blob 地址或 raw 地址；不追随重定向。不下载相对依赖文件，内容上限 1 MiB。补丁可包含上游表达式及插件加载配置，只选择信任的来源。

“验证插件”只检查宿主中的加载初始化，不证明浏览器命令、面板及交互全部正常；这些功能需要正常打开 Harness 后操作验证。维护页新增 Canary 临时环境诊断与有界组合缩小；命令、面板及实际交互仍明确未验证。

## 本轮复核补充（普通操作即可）

- 草稿：编辑未保存的补丁路径／顺序，切到维护再返回设置，内容应保留；点击放弃修改可撤销。暂时连接错误后草稿也保留，但服务操作不可用，不能显示失效的 Web 会话。草稿只在当前 Launcher 的内存中，退出后消失。
- 重试引用：若维护中的近期请求显示“未找到服务器记录”，先检查当前版本和恢复状态，再按明确确认释放本地引用。释放本身不会重做操作，也不会删除服务端历史；不要为验收专门制造断线或等待一天。
- MSI 被动卸载：使用 `/passive` 时保留 Nexus 数据且不询问清理；普通交互卸载仍提供清理选择。这属于可选部署专项，不要求普通用户运行命令。

## 10. Canary（正常操作即可）

停止 Harness，在维护页点击“运行隔离诊断”。预期显示启动、插件加载与 Web 文档结果，交互功能显示尚未验证；原 profile、当前选择和插件启用状态不变。若自然遇到加载故障，可运行“查找失败插件组合”，结果仅为已复现组合，不自动禁用。运行中点击取消，等待清理完成，再正常启动 Harness。不要专门安装有问题的插件。

运行中应显示当前轮次、阶段、已耗时和正在检查的组合，完成轮次可以逐项查看；这些不是完成百分比。再次运行后，历史列表仍可打开之前的报告，最多保留 10 份正常归档。空间不足会在复制依赖前阻断，不要求人为填满磁盘来验收；无法自然覆盖时记未覆盖。

隔离的是临时 profile 与 HOME，不是系统沙箱。Nexus 不主动修改源 profile，但运行的插件仍可访问系统和网络，因此诊断只应针对自己信任的插件执行。

## 11. 界面与恢复入口

设置中切换四个分组，修改未保存内容后切换分组并返回，草稿应保留。调整窗口大小，检查表单、按钮和错误详情可读。侧栏版本入口可直接管理安装版本。

Nexus 记录恢复：打开维护或损坏恢复页，在“恢复时间”选择已有历史点，点击“一键恢复”。系统先停止 Harness、私有备份当前记录，再恢复 Nexus 的当前配置档选择与已知配置档名称，重启 Agent 后保持恢复暂停。核对所选配置档和 Agent 状态；不会恢复 Harness 文件、插件、会话或版本槽。无真实备份时显示无可用恢复点，不要求用户填写内部字段或人为破坏文件。

补丁更新预览可取消后再次预览；长行差异会提示截断。应用前修改草稿会使旧预览不可应用，须重新预览。失败请提供项目编号、构建编号、截图和脱敏诊断，不发送私有备份。

预览显示剩余有效时间，到期后不能应用，须重新预览；缺少旧正文时明确提示没有可比较基线，不将其解释为全部新增。窗口恢复后状态应及时刷新，后台和稳定失败状态会降低查询频率。

## 12. 外部 Harness

使用自己已经准备好依赖和构建产物的可信 RC1 或更早目录。停止 Harness 后选择该目录，核对“外部 Harness”、实际路径与版本，再执行检查、启动、Web 和 DSH 终端操作。Nexus 不应执行下载、构建或依赖安装；缺少文件时应说明原因，不能悄悄改用受管版本。

停止后切回受管版本，确认原版本槽仍可用。解除外部关联后原目录应完整保留。无需删除或破坏源文件来制造故障；用户自行更新外部目录后，再次检查应要求确认变化。DSH_HOME、项目文件与程序目录分别配置，不能把它们混为一谈。

如外部目录位于测试虚拟机，可在第 6 项卸载验收时一并检查目录仍存在。不要为测试把唯一工作副本放入 Nexus 管理的数据或版本槽目录。

大型目录的完整检查可能需要数十秒；此前 RC1 样本单次约 23 秒。点击启动会由后端在本次事务中完整检查一次，启动前再轻量核对身份与关键文件，不重复扫描整个目录。主动点击“检查”仍是独立的完整检查。超过预算会提示检查失败，不能把它当成程序已经启动。

首次引导可直接选择“使用已有目录”，不需要先安装受管版本。外部来源激活时，版本页仅准备受管版本槽，不改变当前外部来源；需要切回时使用明确的来源选择入口。编辑来源遇到配置冲突后，可主动放弃草稿加载已保存值，再重新编辑。检查结果的修复按钮应进入对应页面，修复后可返回重查。

## 13. 缓存与恢复辅助

维护页生成清理预览，查看补丁缓存、私有恢复备份各自容量与保护原因。仅勾选明确无引用的补丁缓存；当前/上一配置、禁用项、有效预览和下载中的缓存都应保留。存在快照时整类缓存保守保留，没有可清理项也属正常。私有恢复备份不自动删除。

未来/未知格式、过期的当前记录版本、损坏恢复点和未结束事务均应拒绝恢复并保留原件。自动化使用隔离临时目录注入故障，不将其写成自然发生的故障验收。

恢复时间来自实际保存过的配置档目录记录，最多保留 64 个有效点。技术详情可查看恢复前备份位置；无需手动核对摘要或替换文件。历史保存失败不影响正常配置切换，历史目录不可用时恢复页应说明错误。
