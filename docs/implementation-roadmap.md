# Nexus 实施与验收清单

基线：2026-09-07 用户实施清单。既有审查缺陷（D）与新增能力（F）分别跟踪，按同一优先级推进。

## 发布与实现边界

- P0：确认的数据损失、严重安全问题、Agent 崩溃或普遍无法安装/启动，立即停止发布并修复。目前没有已确认 P0。
- P1：核心流程、恢复能力或发布可信性问题；下一次正式发布前完成。
- P2：便利性、可解释性和长期体验；全部纳入范围，不能因原审查等级较低而遗漏。
- 恢复模式要求 Agent 正常运行；允许 Harness 暂停运行。Agent 崩溃不能通过“恢复模式”掩盖。
- 普通机器使用内置运行时；允许首次安装/切换未安装 Harness 时执行其 Node/npm/pnpm 构建。Nexus 安装、升级、卸载不得现场编译。
- 不修改上游 Harness 源码或替上游修复 fs-ext 原生编译要求；不引入数据迁移。数据路径只改变访问指向。
- 空值继承原始配置；显式 false、端口 0 等有效值不能误当成空值。
- 不创建新 worktree，不提交未经请求的 commit，不自动更新虚拟机安装或回滚其数据。

## 实施顺序

1. 修复并验证既有 P1：数据保护、进程归属、Agent 发现、恢复事务。
2. 发布可信性与完整内置运行时；先修旧产物混入和混合运行时缺 npm，再建立身份/清单。
3. 诊断与集中启动检查，同时修复首次路径创建和特殊字符路径。
4. Harness 恢复模式与快照中断恢复，验证暂停→修复→检查→重启。
5. 版本能力与统一操作规则。
6. 其余审查 P2 与新增 P2，先编辑可靠性和数据管理，再引导、离线部署及 Windows 集成。

## 第 1 步真实验收材料

仅在测试虚拟机或可恢复的测试环境执行。不要在存有唯一用户数据的机器上验证清理。

- 保留原安装信息及测试数据副本；覆盖安装本次修复包，确认 Agent 在线。
- 启动、停止、再次启动 Harness；停止后确认后代进程/端口不残留。分别验证关闭窗口、托盘退出并保持服务、托盘停止服务并退出，结果应与按钮说明一致。
- 普通卸载选择保留数据，重装后确认配置、Harness 版本及测试会话仍在。
- 自定义 Harness home 位于 Nexus 数据树内时，确认清理 Nexus 数据后测试会话仍保留；重装后再次清理仍保留。
