# 故障处理

[English](troubleshooting.en.md)


先记录 Nexus 版本、构建编号、系统和架构，再保留原始错误。以下步骤不要求删除 Harness 用户数据。

| 现象 | 检查与处理 |
| --- | --- |
| `Resolve the blocking startup checks…` | 查看启动检查中具体 `blocked` 项；这是总括消息，不是根因 |
| `configured_path_missing`、Node 启动程序不存在 | 对比“下次启动输入”与当前解压目录，检查内置 `resources/runtime`；确认是否保留旧固定路径 |
| `ENOENT … app-update.yml` | 确认运行的是完整发行包；该文件在 `resources` 下，不能只复制 EXE。已检查的 v0.1.7 Windows x64 ZIP/EXE 均包含它 |
| 已保存运行时，启动仍用旧路径 | v0.1.7 已知问题，已在 v0.1.8 修复；请使用完整新版安装包。临时处理需同时核对运行时与高级启动程序，不要只改一处 |
| 配置 JSON 解析失败 | 根据错误定位文件、行列，保留备份，使用修复引导或恢复上一份有效配置；不要无差别重置全部目录 |
| 插件 Loader 报错 | 导出原始堆栈，运行兼容性检查，确认插件来源与声明；检查 Nexus/Harness 版本，不能把失败全部归咎于用户插件 |
| 中断操作等待恢复或清理 | 通过界面重试恢复/取消；不得仅删标记绕过进程所有权检查 |
| 无回滚健康证据 | 按提示完成当前版本认证就绪检查，或使用明确提供的手动确认路径；版本指针不是健康证据 |
| 通知不出现 | 核对分类、通知条件、监听连接、系统勿扰和权限；终端提醒还要求监听终端保持打开 |

## 移动便携目录后无法启动

已观察到 v0.1.7 将首次自动选择的内置运行时保存为旧绝对路径。v0.1.8 会按 `bundled` 来源重新解析当前安装路径，并同步关联的启动程序；明确指定的外部路径不会被猜测替换。若旧设置已被标为外部来源，需要明确重新选择，不能根据目录长相自动改写。

## 诊断与恢复

Agent 不可用时仍可尝试 Launcher 启动诊断。启动自检会阻止存在阻塞问题的 Harness 启动，修好后重新检查并由用户启动。旧记录若缺少可验证进程身份，可能需要按提示重启计算机一次；普通路径配置错误不应要求重启计算机。

反馈时附最小复现、原始错误、版本、构建编号和脱敏截图。诊断包也应检查后再分享，不公开令牌、API key、私人会话或完整配置。参见[安全报告](../SECURITY.md)。

## Nexus 诊断门槛

- **阻断**：本次启动失败。展示分类、原始证据、处理建议，以及 Nexus 可协助的设置、配置选择、插件检查或日志入口。
- **功能受限**：上游明确报告可选插件未激活，同时隔离进程已通过认证 Web 就绪检查；不阻止使用，不自动禁用插件。
- **提示**：版本声明和补充线索不作为阻断依据；无关失效回退链接不显示为故障。
- **原因未确认**：保留原始失败，仍阻止失败的启动；不提供无证据的插件责任判断。

错误签名依据安装的 `deepseek-ai/deepseek-harness` 提交 `ddefc45fbc7f8e46dd73185e68295696d1297887`（`dsh-v0.1.6-alpha.2`）中的 `packages/boot/app-boot/src/index.ts`、`profile.ts`、`profile-resolution/resolver.ts`、`vendor/loader/src/config/tree.ts` 和 `apps/cli/src/args.ts`。规则覆盖配置读写/解析、保留配置名、缺失配置包、模块缺失/导出接口、受管布局/解析冲突、重启要求、补丁目标、端口/权限、必需插件/服务和就绪超时。旧版保留 loader 错误判断；未知格式保留原文，不承诺穷尽上游或第三方插件的任意异常。

依赖安装、补丁编辑、版本切换及禁用插件均由用户明确操作。诊断不会自动改写配置、安装依赖、删除文件或关闭无关进程。

## Desktop、准备等待与插件阻塞

- 没有 Desktop 选项：检查所选受管 Harness 和平台是否支持。Windows ARM64、Linux ARM64 当前仅显示 Web。
- 准备耗时较长：查看阶段与耗时，必要时取消；检查本地资源和磁盘空间后重试。离线资源缺失或版本不匹配时，应使用匹配的完整 Nexus／离线包，不应联网临时补装。
- 服务一直等待：依据声明和原始错误查找提供方，等待中的消费者不自动等于故障插件。只在证据明确并确认后停用相关插件，再复检、重试。
- 离线导入失败：检查系统、架构、包完整性与校验结果；仅配置包不能当作完整环境。
- Desktop 已打开但模型或工具失败：查看官方客户端的错误与日志，Nexus 不负责所有运行中业务错误。

参见[启动覆盖](startup-failure-coverage.md)和[桌面端说明](harness-desktop.md)。
