# 配置与生效时机

[English](configuration.en.md)


本文以 v0.1.8 为基线；运行时路径与保存修复已随该版本发布，v0.1.7 仍可能受影响。见[变更记录](../CHANGELOG.md)。

## 保存、下次启动、当前实例

| 设置 | 保存后的行为 | 是否影响当前 Harness |
| --- | --- | --- |
| Node、pnpm、Git 运行时选择 | 后续启动和依赖操作读取新值；运行时检查需手动刷新 | 不替换已运行进程 |
| Harness 启动参数、数据目录、profile、配置补丁 | 后续启动使用；部分操作要求先停止 Harness | 不在进程中热替换 |
| Harness 更新源 | 后续拉取/准备使用；进行中的更新需先结束 | 不改变当前版本 |
| 快照设置 | 后续快照操作读取；活动操作受互斥保护 | 不修改当前会话 |
| 通知分类与条件 | 保存后由通知链路读取 | 通知插件装载开关需重启 Harness |
| 主题、语言、缩放 | 当前 Launcher 界面应用 | 不改变 Harness 配置 |
| 自动更新开关 | 控制后续自动检查；手动检查独立 | 应用更新时才停止 Harness |
| Agent 日志级别 | 下一次 Agent 启动使用 | 不热改运行中的 Agent |

“下次启动输入”是配置解析结果；“当前实例启动输入”是该实例启动时记录的事实。两者不同并不一定是错误。保存成功不要求重启整个 Nexus 才能更新下一次 Harness 启动输入。

## 内置与外部运行时

开发版本默认使用随包 Node/npm/pnpm 与完整 Git 命令行；显式设置的工具路径优先。`npm` 属于所选 Node 组合。缺失的所选工具会报错，不自动使用系统 PATH 的同名工具。完整 Git 随离线包迁移，旧离线包没有 Git 时使用当前 Nexus 随包 Git。此变更尚未发布，不代表既有 0.1.10 安装包已经包含完整 Git。

当前源码按运行时来源解析：`bundled` 跟随当前安装目录，显式外部路径保持用户选择。旧版自动生成的绝对路径可能残留；不能仅通过目录名称猜测用户是否有意固定它。

运行时保存与自动生成的 Node 启动入口保持关联；独立指定的启动程序仍有自己的优先级。清空运行时固定路径不等于清空另行指定的自定义启动程序。

## 环境变量与配置冲突

外部环境变量可能覆盖文件设置，界面会提示相关覆盖。环境变量由进程继承，改变父进程环境不会修改已经启动的子进程。不要将这个规则误认为普通设置必须重启 Nexus。

配置保存使用 revision 检查；发现其他操作已改配置时，保留草稿并刷新后重试，不以旧内容覆盖新内容。运行时、版本切换、恢复等互斥操作仍需等待完成。

## 数据与补丁

修改数据目录不会迁移文件。运行补丁通过所选 Harness 支持的方式叠加，顺序和启用状态影响结果；启动输入说明不是上游合成后的全部最终配置。不要把诊断、补丁或配置文件中可能存在的密钥直接发到公开 Issue。

## Web 与官方 Desktop

Web 配置档可从工作台或配置与插件页面切换；官方 Desktop 在自己的窗口中管理配置。两种模式共享受管版本与数据，切换模式、改版本或导出数据前先停止当前运行。Desktop 使用锁定的离线运行时，不能把 Web 运行时设置理解为可任意替换 Desktop 的运行时。见[桌面端说明](harness-desktop.md)。

## Harness 停止时管理插件

所选 Harness 自带官方插件管理器时，Nexus 调用该版本的 `listBundles`、`setBundleEnabled`、`inspect`、`installBundle` 和 `removeBundle` 实现。修改前必须停止选中的配置档，管理必需组件沿用上游保护。禁用保留已安装依赖；新安装的插件保持禁用，直到用户明确启用。管理操作不加载用户插件。旧版 Harness 保留兼容入口；官方管理器失败时不会静默改用旧写入方式。包脚本批准仍由 Harness 处理，Nexus 不自动批准脚本。

快照与检查点以本机时间作为标题。详情在侧边抽屉中默认显示可读字段，可切换“源码”。

## 离线配置档修复

在“维护 → 离线配置档修复”中选择目标配置档，无需切换当前配置或启动其插件。损坏的配置档也会列出。请先停止 Web、Desktop 和 DSH 终端。

可以检查和编辑 `package.json`、`cordis.patch.yml`；单文件限制 32 KiB，超限会明确拒绝，不截断内容。保存前校验 JSON/YAML 与基本结构，保存后回读。每次保存或恢复前保留精确的原文件恢复点；官方插件启用、禁用、移除和安装操作也会先备份这两份文件。恢复点仅回退配置文件，不能恢复已卸载的插件依赖。原始恢复点可能包含故障，恢复后仍会显示诊断。

文件在编辑期间变化时拒绝覆盖。缺包使用同页的本地依赖检查；格式正常但插件报错时使用官方插件管理，不按缺失服务名称猜测故障插件。格式检查通过不等于兼容性或实际启动通过，应前往工作台启动对应模式验收。不会自动重启 Harness，也不会创建所谓安全模式配置档。

## 先启动，失败后诊断

Web 和 Desktop 正常启动不预跑隔离插件诊断，也不为诊断复制配置档或扫描整个依赖树。仍会执行必要的运行时、配置与进程互斥检查；Desktop 首次运行所需的官方产物准备保留。浏览器入口继续等待客户端就绪。

启动失败后保留本次错误。只有明确的模块缺失/导入失败才检查本地依赖；锁文件和本地包身份均匹配时补齐缺失链接，保留修复记录，最多重试一次。不会下载依赖、覆盖已有链接、禁用插件或修改配置来尝试启动。停止、版本切换或配置变化会取消恢复；普通插件异常和超时保留诊断供用户处理。完整兼容性自检仍可手动执行。
